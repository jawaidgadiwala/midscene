# 桌面端运行时到底截取了什么

在把 Midscene 的 `computer` target 指向一台你还用于其他事情的机器之前，值得先了解
这一点。

## 整块屏幕都会发送给模型

桌面 target 没有「窗口」的概念。每一步都会截取**整个显示器**：被测应用、当时可见
的所有其他窗口、菜单栏，以及运行过程中弹出的任何通知。这张图会：

1. 发送给模型服务，并且
2. 内嵌进 `midscene_run/report/` 下的 HTML 报告。

报告是自包含文件，截图直接内联其中，因此一份报告的敏感程度等同于截图那一刻的屏幕
内容。把它附到缺陷单上，就等于把当时屏幕上的一切都附了上去。

这是桌面端视觉驱动方案的固有特性，不是缺陷。之所以在此说明，是因为它很容易被忽略，
直到报告已经分享出去。

## 减少暴露面

- **在干净的桌面上运行**：使用专用用户账号或一个全新的 Space，把无关窗口挡在画面外。
- **打开「勿扰模式」**：运行途中出现的通知同样会被截取并发送。
- **把 `midscene_run/` 当作敏感目录**：它默认已被 gitignore，请保持这一设置，并及时
  清理旧报告，而不是任其堆积。
- **优先使用更精确的平台**：只要能在浏览器中触达，Web target 只会截取视口范围。

## 关于录屏权限

macOS 要求运行 Midscene 的终端拥有「屏幕录制」权限。缺少该权限时，截图会静默地返回
一张全黑图片；模型随后会报告「看不到该元素」，看起来像定位失败，而不是权限问题。

如果每一步都报告屏幕为空或全黑，请先检查
**系统设置 → 隐私与安全性 → 屏幕录制** 中你的终端是否已被授权，再去排查其他原因。
